# v1.5.1

> **Stable Release** · October 14, 2026 · [NuGet](https://www.nuget.org/packages/WinUI.TableView/1.5.1) · [GitHub Release](https://github.com/w-ahmad/WinUI.TableView/releases/tag/v1.5.1)

WinUI.TableView v1.5.1 is a maintenance release focused on improving stability, layout consistency, column resizing, and performance across WinUI and Uno Platform. This update also introduces Polish localization and improvements to the sample application and automated testing infrastructure.

## 🐛 Fixes

- Fixed an issue where scrolling with frozen columns could produce a negative-width header clipping rectangle, causing an exception on WinUI or disappearing column headers on Uno Platform by [@SolidRockProgrammer](https://github.com/SolidRockProgrammer) in [#438](https://github.com/w-ahmad/WinUI.TableView/pull/438).
- Fixed column resizing in `Preview` mode, where double-clicking a column divider to auto-size could cause misaligned cell content, incorrect selection borders, or unexpected visual offsets by [@w-ahmad](https://github.com/w-ahmad) in [#447](https://github.com/w-ahmad/WinUI.TableView/pull/447).
- Fixed alternating row colors becoming inconsistent after scrolling, recycling rows, or modifying the items collection by [@w-ahmad](https://github.com/w-ahmad) in [#451](https://github.com/w-ahmad/WinUI.TableView/pull/451).
- Fixed column resizing unexpectedly scrolling the table horizontally, particularly after editing a cell. Row size changes now preserve horizontal scroll position, while row details expansion continues to bring the affected row into view when appropriate by [@w-ahmad](https://github.com/w-ahmad) in [#455](https://github.com/w-ahmad/WinUI.TableView/pull/455).
- Fixed row details visibility on Uno Platform when a row's selection state changes in `VisibleWhenSelected` mode by [@w-ahmad](https://github.com/w-ahmad) in [bb90f6b](https://github.com/w-ahmad/WinUI.TableView/commit/bb90f6b756096e4d524c5220c8b3262e2da10295).
- Fixed incorrect column header alignment and clipped selection checkboxes when `TableView` is displayed with an empty `ItemsSource`. Header offsets and scrollbar margins are now updated correctly when the collection or header configuration changes by [@w-ahmad](https://github.com/w-ahmad) in [#459](https://github.com/w-ahmad/WinUI.TableView/pull/459).

## Enhancements

- Added Polish (`pl-PL`) localization, providing translations for the control's existing resource strings by [@bartazalbln](https://github.com/bartazalbln) in [#446](https://github.com/w-ahmad/WinUI.TableView/pull/446).
- Reduced redundant object allocations by reusing common bindings and brushes across cells, rows, and headers. Shared resources are maintained per UI thread to preserve thread affinity by [@w-ahmad](https://github.com/w-ahmad) in [#448](https://github.com/w-ahmad/WinUI.TableView/pull/448).

## 🧪 Testing and Maintenance

- Made the main WinUI sample application compatible with Native AOT and trimming, removing the need for the separate `AotTestApp` project by [@w-ahmad](https://github.com/w-ahmad) in [#450](https://github.com/w-ahmad/WinUI.TableView/pull/450).
- Fixed the CI workflow to ensure automated tests are actually executed and test failures are correctly reported by [@w-ahmad](https://github.com/w-ahmad) in [#452](https://github.com/w-ahmad/WinUI.TableView/pull/452).
- Expanded cross-platform test coverage by sharing existing WinUI test sources with Uno Platform test projects and running independent platform test suites in CI by [@w-ahmad](https://github.com/w-ahmad) in [#460](https://github.com/w-ahmad/WinUI.TableView/pull/460).
- Migrated WinUI tests to an unpackaged MSTest runner using Microsoft.Testing.Platform, removing MSIX deployment requirements and enabling direct execution through `dotnet test` by [@w-ahmad](https://github.com/w-ahmad) in [#462](https://github.com/w-ahmad/WinUI.TableView/pull/462).
- Improved sample application development and packaging workflows, including unpackaged debugging and a dedicated script for generating Microsoft Store upload packages.

## Documentation

- Corrected the conditional styling documentation to clarify that styles are evaluated in order, the first matching style wins, and column-level styles take precedence over TableView-level styles by [@w-ahmad](https://github.com/w-ahmad) in [#453](https://github.com/w-ahmad/WinUI.TableView/pull/453).
